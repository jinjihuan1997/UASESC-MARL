# 原系统与严格指令诊断的重新核对

本次只新增审计脚本和记录，没有修改环境、训练参数、检查点、平均表或论文。原稿 main.tex 的 SHA-256 仍为 e5476c99d5a6766ea43bc44f467829e1bb48feeb1f615ec0d0cd9a5f11797243。

## 原项目研究的对象

原稿的业务链为：DS 视频采样 → UAV 缓存与语义编码 → SUT 和卫星转发 → RCC 重建视频。网络控制要在有限资源下兼顾重建质量、信息新鲜度和传输开销。RCC 指令是服务目标上下文。SUT 策略分配各 UAV 的卫星资源，UAV 策略选择语义模式，并在原默认代码中输出调度评分权重。调度代码把策略输出落实为具体的缓存更新发送集合；训练根据执行后的共同奖励更新策略。

语义编解码模型与网络控制策略是不同层次。采用用户指定的平均表时，RL 每步查询模式和信道对应的预计质量、载荷，再模拟缓存及 AoI 变化；这不能描述成每一步都实际执行视频编解码。

## 最近改变了什么

instruction_priority 版本仍在采样前使用质量和缓存掩码；由于同时决策，事前掩码不读取当前尚未确定的 SUT 资源分配，最终预算由执行器检查。

strict_instruction 诊断为了移除间接即时指令信息，把两种方法的 UAV 模式掩码都设为全可选，同时让 SUT 待传载荷特征不依赖当前质量门限。质量、缓存和资源的最终执行检查保留。于是策略现在可以提出不符合当前质量要求的模式，再由执行器回退。

这不是原有完整控制接口的等价改写。它是一个额外的输入消融实验，不能因为该实验出现高回退率，就认定原设计的策略一直没有作用。两版执行函数相同只说明相同动作下物理结果相同，不意味着采样到的动作及训练结果相同。

## 需要纠正的判断

1. “系统换掉”具体指环境中的约束调度遍历其他可执行模式；不存在另一个 AI 接管，也不是训练模型或指令被替换。
2. 原项目的 RL 与约束调度共同构成方法；约束调度存在本身不证明代码有错或 RL 无效。SUT 资源分配的作用也不能被 UAV 模式改选率代替。
3. 大量改选的数字来自最近全模式开放的诊断版本，之前解释没有充分限定版本，容易错误归因到原系统。
4. 原默认代码有调度权重输出，当前实验固定为 AoI 优先。采用平均表时，同一 UAV 的各 DS 在同一模式下质量与载荷相同，原正权重评分对候选 DS 的排序退化为 AoI 排序（平分时仍需索引裁决）。原来的接口、当前表下的有效控制自由度、后来删去的冗余输出要分别描述。
5. 指令通过画质门限、允许模式和策略观察共同影响系统，本来就是原设计；验证这种整体响应，与验证“显式指令字段在相同约束之外的额外收益”是两个问题。后者不显著，不能直接否定前者。
6. 当前证据不支持直接删去约束调度或宣布全量重训。主实验应明确完整接口的定义；严格输入消融单独报告，并分别检查模式选择、SUT 资源分配及公共调度贡献。
