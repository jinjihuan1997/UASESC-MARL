# MDP与训练策略重新审查

本次结论：优先修正稿件与实现的决策时序，补齐任务时间语义，再改善输入和训练过程。不要把之前的“协同困难”当作已经唯一确认的优化失败原因；HAPPO本身就是针对合作策略更新设计的，共享奖励并非代码错误。

这是设计审查和小规模接口验证。没有改动生产代码、奖励、原模型或稿件，也没有启动训练。以下建议的提升效果尚未经过新训练验证。

## 二、建议的一个物理时隙流程

**当前状态和指令 → SUT分资源 → UAV收到当前预算 → 三架UAV选模式 → 共同执行器发送 → 更新缓存/AoI → 计算一次团队奖励 → 进入下一槽。**

具体实现应拆成两个控制阶段，但仍然只有一次物理环境推进：

1. `observe_pre_allocation()`提供SUT观测和时隙开始的critic状态。
2. SUT采样一次资源动作，计算含0.05下限的真实份额和预算。
3. `observe_post_allocation()`生成UAV输入及当前质量/预算可行掩码；此时不改变缓存、时间、AoI或信道。
4. UAV基于这个输入采样模式，执行原有共同调度器；沿用原来的缓存准入、生成时间和AoI转移。
5. 每个物理槽仅记录一个reward并折扣一次。不能把两个控制阶段当成两个普通环境时隙，额外计算两次奖励或把折扣变成gamma平方。

联合策略应明确写为：

\[
\pi(a_t^0,\mathbf m_t\mid s_t)
=\pi_0(a_t^0\mid o_t^0)
\prod_{n=1}^{3}\pi_n(m_t^n\mid o_t^n(s_t,a_t^0),g_t).
\]

buffer必须保存每个actor真正用于采样的输入、可行掩码和log probability。PPO更新时重放同一条已采样的SUT动作所对应的UAV输入，不得重新抽一个资源动作来计算旧样本概率。HAPPO的顺序策略更新与时隙内“先资源后模式”是两种不同的顺序，都要分别验证。

此流程需要时隙开始的预算广播；稿件已假设这一流程。实施时仍应明确控制信令开销或忽略该开销的假设，并让所有对比方法采用同一物理时序与可行性规则。

## 三、状态设计与任务结束方式

建议区分环境真实状态、critic输入和各actor可得到的观测，而不是把一个不完整的观测向量直接称作完全可观测MDP状态。

环境状态至少覆盖：当前指令、指令过程的历史状态、任务时钟、缓存占用、缓存数据年龄、RCC AoI、当前信道、当前profile及固定拓扑参数。资源分配后的控制阶段另外包含本时隙资源动作。随机拓扑若在回合间变化，可把大尺度损耗/拓扑上下文提供给critic；actor是否能获得应按通信假设明确。

建议的输入：

- **SUT**：当前指令、剩余时间、各链路信息、每架缓存数量、缓存数据对应的AoI总和/最大值、待传负载、必要的模式质量—载荷汇总。
- **UAV**：当前指令、剩余时间、本时隙实际预算、本地缓存占用、缓存数据年龄、各DS AoI、每个模式一次质量/载荷值、UAV身份或已知链路上下文。
- **critic**：两级控制需要的全局物理信息、时钟和已发生的指令切换历史。当前critic本来已经接收指令，不能把`instruction_conditioned_critic=false`误解为“critic看不到指令”；该开关主要控制专门的多头结构。

AoI输入使用`A/8`仅改变网络表示，不能顺手把物理上限从600改成8，也不能将输入一律裁到1。为避免指令在重复特征中被稀释，可在后续对照中用单独的16维指令编码与状态编码融合；它仍由RL决定动作，不能给质量指令硬接中档、AoI指令硬接低档。

对“不输入指令”的消融，所有新增的指令编码、指令路由或指令历史字段都要检查是否泄露指令。critic按照原CTDE协议可以继续看到指令，actor不应通过新的隐藏路由直接获得它。

### 600槽到底表示什么

当前稿件P1是600槽有限期的累计效用。按这一表述，首选是：**保留任务末尾真正终止、不bootstrap，同时向actor/critic提供剩余时间**。构造检验已证实现在的输入无法直接分清“还剩450槽”和“只剩1槽”。

如果研究目标实际是持续运行、600仅是采样窗口，则应改为truncation：从结束前真实终态bootstrap，不能拿自动reset后的新初态值代替；GAE递推仍应在reset边界断开，避免跨回合串联。这属于另一种目标定义，不应悄悄改入原有限期实验。终止、截断与剩余时间的区别参见[Gymnasium官方说明](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/)。

另一个需要说明的近似是：P1是不折扣累计效用，训练使用gamma=0.99。它削弱较远未来对当前回报估计的影响，但不等于把所有回合后半段训练样本降权。第一轮接口对照建议保持gamma=0.99；修正时间状态后，单独用gamma=1检验有限期目标对齐，避免一次改动太多因素。

## 四、训练方式怎样改才有可验证性

之前恢复学习率续20万步的负结果，不证明更长训练一定无效，也不证明全局奖励必须拆成局部奖励。它说明目前没有证据支持仅靠恢复学习率就能解决。

### 第一轮：先隔离资源学习对模式学习的影响

在时序和任务语义修正后，为以下三组采用同一网络表示、奖励、指令序列、样本预算和评估协议：

| 组别 | 训练过程 | 诊断目的 |
|---|---|---|
| 联合训练 | 从头训练SUT和三架UAV，共100万步 | 修正接口后的基准 |
| 仅模式训练 | SUT资源固定为各1/3，只训练三架UAV，共100万步 | 判断移除资源波动后，模式协同是否能学出来 |
| 分阶段训练 | 前30万步固定各1/3资源、只训UAV；后70万步开放SUT和UAV联合训练 | 判断模式预训练能否帮助后续联合优化 |

第一轮保持原随机切换指令分布，不同时加入新的固定指令课程，以便区分资源冻结的作用。所有阶段都允许策略自行选择全部保留模式；不使用规则模式标签，不把“必须全中档”写进执行器。

三种子85/218/966，共9次100万步训练，总900万环境步；每组100万步是250个4000步的采样—更新循环，不是100万回合。网络相同的对照要匹配初始权重，并使用独立于动作随机流的相同外生轨迹。架构变化时不能强求形状不同的初始权重哈希一致。

“仅模式训练”应与相同固定资源下的规则模式基线比较，不能直接将其与可自由分资源的R_instruction比较后宣称同条件胜负。分阶段模型的最终联合评估则可以回到完整规则方法对比。

首次对照保留actor lr=1e-4、critic lr=4e-4、rollout=400×10、PPO epoch=5、clip=0.1、gamma=0.99、GAE lambda=0.95和原优化日程，以隔离接口及分阶段训练因素。模式冻结阶段需跳过SUT梯度更新，常量资源动作不能伪装成由随机SUT策略采样的动作参与PPO概率比。

### 第二轮：第一轮有方向后，再比较优化日程

下列为预先指定的候选设置，尚未验证为最优，不应全部混入第一轮：

| 参数/结构 | 候选修改 | 原因与限制 |
|---|---|---|
| 学习率 | 初始值不变，前60%预算保持，后40%降到初始的20% | 防止1M末尾降到1/250；必须与原日程对照，前次重启负结果仍有效 |
| 模式熵系数 | 0.008逐渐降至0.001 | 降低后期持续探索；下降太早会锁住错误策略 |
| 资源熵系数 | 与模式分开；候选0.002逐渐降至0 | 两种分布熵的数值含义不同；小数值本身不保证更好 |
| 资源分布 | 可选把均值和浓度分开：alpha=kappa·softmax(z)，kappa按预定日程20→80 | 在近均分情况下，含0.05下限后的份额标准差约0.087→0.045；这是公式值，不是实测提升。须保证采样与log_prob使用相同浓度 |
| 指令训练覆盖 | 均衡覆盖三种指令和六种切换方向；固定指令课程另做对照 | 防止小批次覆盖偏斜；不能仅因AoI原奖励绝对值大就擅自按任务分别标准化优势 |
| critic | 可试共享状态编码+三个指令价值头 | 当前单头已看到指令；多头是结构对照，不是修复缺失输入。跨指令的下一状态值必须取下一指令对应的值 |
| 模式去重 | 当前profile下仅精确合并等价类别，16→11 | 改变动作表示与探索先验，需要重训、同步规则基线和验证全部转移/奖励等价；不直接删成两个动作 |

“看指令”和“不看指令”的主要对比，应在相同新接口及相同训练日程下完成。不能拿旧接口的隐藏指令模型与新接口的显式指令模型作纯指令消融。

## 五、若仍然学不会，再考虑算法结构

第一轮固定资源后仍无法形成有效模式响应，才值得进一步比较动作条件critic与反事实优势：估计其他动作固定时，某架无人机改选模式对长期团队回报的贡献。

这与[COMA](https://arxiv.org/abs/1705.08926)的动机相关，但不能直接把当前一步奖励差替换成长期优势，也不能把全局最大AoI项改成各自局部AoI后继续声称优化同一个目标。

若尝试三架UAV共享参数，应作为共享UAV actor的MAPPO或重新推导的组策略更新方案；不能简单开启旧HAPPO的share_param，因为更新一个共享网络会同时改变其他agent的策略概率，影响顺序更新因子。当前TensorTrainer本来也拒绝share_param、RNN及按指令优势归一化开关。HAPPO顺序更新本身是处理合作策略优化的正式方法，参见[原论文](https://arxiv.org/abs/2109.11251)，不能把没有逐架反事实奖励当成实现错误。

## 六、实施与验收顺序

1. 新建版本化代码与配置；旧源代码、checkpoint、profile和结果保持冻结。稿件如需修改，只在Manuscript目录直接新增tex。
2. 先完成SUT→预算→UAV时序、buffer/log_prob、剩余时间和终止语义；固定给定动作下的物理转移和奖励应与原执行器一致。
3. 无损去掉重复质量特征，调整独立观测尺度，补合理的SUT汇总信息。增加的可观测信息要在论文及对比协议中写清楚。
4. 检查CPU/tensor一致性、每物理槽仅一次状态推进/奖励、真实末态bootstrap语义、掩码概率重放、无未来指令泄露、隐藏指令消融不被新路由破坏。
5. 运行上述三种子三组预算对照；记录完整原13场景结果、逐指令回报和质量/AoI、切换后恢复曲线、联合模式分布及资源波动。诊断用既有种子；方案确定后使用预先固定的新评估种子确认，不根据这些种子的结果继续调参。
6. 只有在相同总预算比较中出现稳定收益，再进入更长训练并补隐藏指令消融及其他算法。分阶段预训练步数也必须计入总训练预算。

不以“所有质量任务一定全中档”作为最终正确答案。它是当前平均表和现有测试场景下的强参考；最终判断仍以同一原始团队目标、指令响应和物理指标为准，不承诺上述修改必然超过规则基线。
