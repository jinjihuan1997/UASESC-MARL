# 三个新种子的联合训练与交替训练

每个模型从随机初始化开始训练100万环境步。训练种子为104948945、111868397、160441552，在训练和新验证前由操作系统随机源一次产生；全部报告，不替换落后种子。每个种子运行joint和alternating两臂，共600万环境步。

两臂都使用原HAPPO、3个连续资源份额和每架UAV的16选1模式。SUT先分资源，UAV接收实际预算后选模式；保留当前SC平均表、物理动态、指令切换生成规则和全局奖励。actor学习率1e-4、critic 4e-4，短试内恒定；网络规模、PPO和GAE参数两臂一致。joint为相同预算/优化器设置下的联合更新对照，不冒称旧1200万步模型的续训。

alternating阶段：

| 环境步区间 | 更新网络 | 资源来源 |
|---|---|---|
| 0–40万 | UAV 1、2、3 | 每时隙每环境以1/2概率均分，否则Dirichlet(1,1,1)采样；原0.05份额下限仅应用一次 |
| 40–60万 | SUT | 当前SUT策略 |
| 60–70万 | UAV 1、2、3 | 当前冻结SUT策略 |
| 70–80万 | SUT | 当前SUT策略 |
| 80–90万 | UAV 1、2、3 | 当前冻结SUT策略 |
| 90–100万 | SUT | 当前SUT策略 |

critic全程更新；每阶段重新采集on-policy样本。冻结网络仍接收指令并采样动作，不等于固定模式。不使用贪心得分预测器、额外候选奖励标签或独立局部奖励。

每20万步保存不可变模型快照。新验证采用13个原指令场景×20个新环境种子×600时隙。40万步之前SUT未训练，因此alternating的20万、40万步评估以均分资源检验选模，明确标为诊断；60万、80万、100万步使用完整网络控制器。主要比较固定100万步检查点，不从曲线上事后挑赢家。seed_selection.json另有20个预留最终测试种子，本轮不会运行。

四个简单基线为均分＋固定模式、紧急度＋固定模式、均分＋指令选模、按指令切换简单规则。映射沿用原独立校准结果，并通过现有SUT观测摘要计算资源分配。新验证会重新评估基线，不直接挪用旧环境种子的分数。所有方法遵守共同可行性掩码和AoI缓存调度。

实测4 CPU＋2 GPU并行时，每4000步CPU约1.58–1.96秒，GPU约9.15–16.57秒；GPU当时在执行另一个项目。此次选择6 CPU训练并行，另留CPU运行检查点评估。设备选择依据时间而非得分。六个训练任务固定到CPU 0–5；评估使用空闲CPU，任务总并行上限8。原温控守护只暂停/恢复本次队列，不触碰其他项目进程。

预检覆盖CPU/CUDA所有阶段、冻结网络与优化器不变、预算采样分布、相同初始化和外生环境配对、跨阶段及跨回合的精确断点恢复、模型保存/加载以及独立物理奖励核验。源码、配置、表、种子、规则、预检均在manifest.json记录哈希。
